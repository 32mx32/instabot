# Changelog - Instagram Telegram Bot

## [v2.3.0] - 2026-11-11

### Новые возможности
- Бесплатное скачивание через **yt-dlp**. Apify остаётся резервом для Instagram (`USE_YTDLP`, `YTDLP_COOKIES_FILE`).
- Поддержка **TikTok** (включая `vm.tiktok.com`) и **YouTube Shorts**.
- Распознаются ссылки `/reels/`, `m.instagram.com`, `instagram.com/<user>/reel/`, `/share/`, а также ссылки в середине текста.
- Ссылки нормализуются: параметры `?igsh=` и username отбрасываются.
- `/stats` показывает, сколько скачиваний прошло через yt-dlp и сколько через Apify. Доступ можно ограничить через `ADMIN_IDS`.
- Скрипт `scripts/test_ytdlp.py` проверяет yt-dlp на сервере.

### Исправления
- Скачивание больше не блокирует бота: работа вынесена в отдельный поток, включена параллельная обработка апдейтов (`MAX_PARALLEL_DOWNLOADS`).
- Токен бота больше не попадает в логи: `httpx` переведён на уровень WARNING.
- Отредактированные сообщения больше не вызывают `AttributeError`. Добавлен глобальный обработчик ошибок.
- Файл лога теперь действительно пишется (раньше `bot.log` оставался пустым). Новый путь: `logs/bot.log`, с ротацией.
- Убрана лавина ретраев: было до 27 запусков Apify на ссылку. Запуски акторов ограничены таймаутом 120 с.
- Рабочие ключи Apify больше не отключаются ошибочно: ротация срабатывает по HTTP-статусу (401/402/403/429) и точным фразам о лимитах.
- Уникальные имена файлов: параллельные загрузки не перезаписывают друг друга.
- Проверка лимита Telegram в 50 МБ до отправки.
- Кнопка «Показать комментарий» больше не зависает, если комментарий пропал из кэша.
- Кнопка «Повторить» учитывает rate limit и статистику.
- Тексты `/start`, `/help`, `/stats` отображаются с форматированием, без буквальных `**`.
- `update.sh` больше не перезаписывает серверный `.env` и пересобирает образ.

### Технические изменения
- Код разделён на модули: `links.py`, `ytdlp_downloader.py`, `config.py`, `main.py`. Дублирование в обработчиках убрано.
- Удалён мёртвый код: `get_error_details`, ветка скрытия комментариев, флаг `/w`.
- Docker: Python 3.12, ffmpeg, `.dockerignore` (файл `.env` больше не попадает в образ).
- Версии зависимостей закреплены. yt-dlp обновляется при каждой сборке.
- Добавлены тесты (`pytest tests`).

## [v2.2.0] - 2026-05-29

### Новые возможности
- Добавлена ротация нескольких Apify API ключей.
- Добавлена переменная `APIFY_API_KEYS` для списка ключей через запятую.
- Сохранена обратная совместимость с одиночной переменной `APIFY_API_KEY`.
- Добавлена поддержка переменных `APIFY_API_KEY_1`, `APIFY_API_KEY_2` и т.д.

### Надежность
- При ошибках лимита, квоты, оплаты, авторизации и rate limit текущий Apify ключ временно отключается.
- После отключения проблемного ключа бот автоматически пробует следующий доступный ключ.
- Все Apify ключи логируются только в маскированном виде.

### Документация
- Обновлен `.env.example` с примером `APIFY_API_KEYS`.
- Обновлен README с инструкцией по нескольким Apify аккаунтам.
- Обновлены install/update скрипты для проверки нескольких Apify ключей.
- Версия бота обновлена до `2.2.0`.

### Технические изменения
- Добавлен `ApifyKeyManager` для управления cooldown ключей.
- `retry_apify_request` теперь создает Apify client на основе текущего доступного ключа.
- Приведены команды Docker Compose в документации к формату `docker compose`.
